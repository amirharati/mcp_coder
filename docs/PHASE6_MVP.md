**Purpose:** Build a clean central observability layer (`core/observability/`) as the POC/MVP of the AGENTIC_LOOP_LOGGING separate-product vision; fix live token accounting (BL-335); capture reasoning tokens + session hot buffer; lay training-data schema foundations.

## One-line goal

Replace scattered logging calls in `mcp_server.py` with a clean, adapter-seamed observability layer — then build the Phase 6 capabilities (live tokens, helper wire logs, reasoning buffer, training opt-in) on top of that clean substrate.

## North-star acceptance (dogfood)

After a live `delegate_to_agent` call on `mcp_coder_phase1_e2e`:
1. `model_roles.*.tokens` are **not null** — executor, builder, architect, validation all report real counts.
2. A per-delegation trace file exists with helper LLM inputs/outputs (at `standard` verbosity).
3. `reasoning_content` from the executor (if the model emits it) is captured and visible in `context.reasoning_summary` in JSONL.
4. The builder brief for the *next* delegation includes a reasoning hint from the previous one (hot buffer wired).
5. Setting `capture_for_training: true` in config writes a structured `(task, context, trace, outcome)` tuple alongside the trace.

---

## Strategic context

Phase 6 is the **POC/MVP** of [AGENTIC_LOOP_LOGGING.md](./OTEHR_RELATED_IDEAS/AGENTIC_LOOP_LOGGING.md)'s separate-product vision:

> mcp-coder V1 → first playground → validate the stack → extract as open-source project → integrate here as client → broader community use

The `ObservabilityBackend` adapter seam (D-P6-1) is what makes this extractable. Today: local JSONL/SQLite implementation inside mcp-coder. Later: swap in a full logging product without touching pipeline code — same pattern as `core/engine/` (swap Aider) and `core/host/` (swap Cursor).

## Locked design decisions

| ID | Decision |
|----|----------|
| D-P6-1 | `ObservabilityBackend` abstract interface in `core/observability/base.py`; local implementation in `core/observability/local.py`. All logging calls in `mcp_server.py` go through `obs.*`. No behavior change in P6-001 — just the seam. |
| D-P6-2 | LiteLLM Route A (`litellm.success_callback` at MCP startup) as primary capture mechanism. Backend-neutral; covers all roles (builder, architect, validation, executor turns). No Aider patching. See REASONING_TRACE_REUSE.md §How to capture it. |
| D-P6-3 | Per-delegation **trace files** are separate from `delegations.jsonl`. Canonical JSONL stays lean (hashes + summaries); trace files hold bodies. Path: `~/.mcp-coder/projects/<key>/sessions/<id>/traces/<delegation_id>.jsonl`. |
| D-P6-4 | Three verbosity tiers (configurable): `lean` (token counts + hashes only), `standard` (helper summaries + truncated inputs/outputs, default), `full` (all bodies + reasoning verbatim). |
| D-P6-5 | Hot buffer = in-memory session dict `{delegation_id: reasoning_summary}`. Optional N-delegation persistence in `workspace_history.db` for cross-session reuse. TTL = session by default; configurable. |
| D-P6-6 | Training capture is **opt-in** (`capture_for_training: false` default). When on: full `(task, context_package_hash, trace_ref, outcome)` tuple written to `traces/<delegation_id>-training.json`. Schema must include version tags (mcp-coder git SHA, model versions, pipeline flags, config fingerprint). |
| D-P6-7 | **No behavior change** in P6-001 (refactor only). Existing tests must pass unchanged. New Phase 6 capabilities are additive on top of the clean seam. |

## Milestones

### P6-001 — Observability adapter seam + logging consolidation *(refactor)*

**Goal:** Audit all current logging/telemetry surface; extract into `core/observability/` with a clean `ObservabilityBackend` interface. No new behavior — just the seam. This is the prerequisite for everything else.

**Current surface being consolidated:**

| Module | What it owns |
|--------|-------------|
| `core/logging/delegation_log.py` | JSONL record build + append; verbosity flags; lifecycle events |
| `core/logging/server_log.py` | `ServerLog` singleton → `server.jsonl` |
| `core/pipeline/phases.py` | `PipelineRecorder` — phase timing |
| `core/usage/` (5 files) | Token counts, cost rates, per-role audit (`litellm_tokens`, `role_audit`, `telemetry`, `aider_tokens`, `rates`) |
| `server/mcp_server.py` | ~18 direct calls to all of the above |

**Acceptance:**
- `core/observability/base.py` defines `ObservabilityBackend` with methods covering all existing logging call sites
- `core/observability/local.py` is the concrete implementation backed by existing modules (which may stay in place as implementation detail or be folded in — worker decides)
- `mcp_server.py` imports and calls `obs.*`; no direct calls to `delegation_log`, `server_log`, `PipelineRecorder` etc. from outside `core/observability/`
- All existing tests pass (behaviour identical)
- New `ObservabilityBackend` is swappable: a second implementation (e.g. `NullObservability`) can be dropped in for tests

**Files touched:** `core/observability/` (new), `server/mcp_server.py`, possibly `core/logging/`, `core/usage/`, `core/pipeline/`

### P6-002 — LiteLLM callback + BL-335 live token fix

**Goal:** Wire `litellm.success_callback` at MCP startup (Route A from REASONING_TRACE_REUSE.md). Fix BL-335: `model_roles.*.tokens` not null on live OpenRouter/Gemini delegates. First real new capability on the clean P6-001 seam.

**Acceptance:**
- `litellm.success_callback` registered in `core/observability/local.py` at MCP startup
- Callback captures: `delegation_id`, `role`, `model`, `usage` (input/output/reasoning tokens), duration — correlated via `contextvars`
- After a real delegate on `mcp_coder_phase1_e2e`: `model_roles.context_builder.tokens`, `.executor.tokens` are non-null in JSONL
- `cost_est_usd` computes correctly for all roles
- `test-model` also reports token counts when `--via litellm`
- Replicate steps from BL-335 § replicate pass

### P6-003 — Per-delegation trace files (verbosity tiers)

**Goal:** Implement D-P6-3/D-P6-4: helper LLM inputs/outputs stored in per-delegation trace files at `standard` verbosity. First slice of BL-353-5b.

**Acceptance:**
- After a `delegate_to_agent` call with `standard` verbosity (default): `traces/<delegation_id>.jsonl` exists with one record per LLM call (role, model, prompt_hash, response_summary, token counts, duration)
- At `full` verbosity: same file has full request/response bodies
- At `lean` verbosity: file has token counts + hashes only (no bodies)
- `delegations.jsonl` unchanged (canonical record stays lean)
- `mcp-coder view delegations` still works; trace files are a separate artifact
- Config: `observability_verbosity: standard` (default) in `config.yaml`; env `MCP_CODER_OBS_VERBOSITY`

---

### P6-004 — Reasoning token capture + session hot buffer *(BL-333)*

**Goal:** Capture `reasoning_content` before Aider strips it; build session hot buffer; wire into next delegation's builder brief.

**Acceptance:**
- When executor model emits `reasoning_content`: `context.reasoning_summary` field appears in `delegations.jsonl` (truncated, ≤2k chars)
- Session dict `{delegation_id: reasoning_summary}` maintained in-memory
- `gather_builder_history()` includes reasoning summaries from same-session prior delegates in builder brief under `## Prior reasoning` (token-budget-gated, never truncates spec contract paths)
- `reasoning_summary` absent when model does not emit reasoning (no null noise for non-reasoning models)
- Config: `capture_reasoning: true` default (on when model emits it); `reasoning_buffer_size: 3` (last N delegates in hot buffer)

---

### P6-005 — Training opt-in schema + summarization policy *(optional capstone)*

**Goal:** Implement D-P6-6: training capture flag + extraction-ready tuple schema + initial summarization/retention policy (BL-357 first slice).

**Acceptance:**
- `capture_for_training: false` by default; when `true`: writes `traces/<delegation_id>-training.json` with full `(task, context_package_hash, reasoning_summary, outcome, verify_result)` + version tags (git SHA, model versions, pipeline flags, config fingerprint)
- Schema is self-describing: field names match AGENTIC_LOOP_LOGGING.md trace format so records can be fed into its pipeline without transformation
- `mcp-coder maintenance stats` (new command) reports: `delegation_rag.db` rows, `workspace_rag.db` rows, trace files count + total bytes, `delegations.jsonl` total size
- Summarization policy stub: `observability_retention: session | N_days | forever` in config (enforcement deferred to BL-357; policy stored now)

## Config toggles introduced

| Key | Default | Effect |
|-----|---------|--------|
| `observability_verbosity` | `standard` | `lean` / `standard` / `full` |
| `capture_reasoning` | `true` | Capture `reasoning_content` when model emits it |
| `reasoning_buffer_size` | `3` | How many prior delegate summaries in hot buffer |
| `capture_for_training` | `false` | Write training tuples (opt-in) |
| `observability_retention` | `session` | Policy stub for future gc |

Opt-out env vars follow existing pattern: `MCP_CODER_OBS_VERBOSITY`, `MCP_CODER_CAPTURE_REASONING`, etc.
