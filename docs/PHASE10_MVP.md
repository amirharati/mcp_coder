## One-line goal

Shape Aider's behavior before problems occur, see what is happening while it runs, and handle stalls gracefully — all at POC/partial level sufficient for real-project dogfood.

## North-star acceptance (dogfood)

After live `delegate_to_agent` calls in a real project workspace:

1. **System prefix applied** — `MCP_CODER_EXECUTOR_SYSTEM_PREFIX` is set, its content is prepended to Aider's system prompt, and `policy_applied` on `backend_llm_call` reflects it. Executor behavior measurably shaped by the prefix (e.g. "stay within spec files, don't ask to add more").
2. **Live progress visible in Cursor** — `ctx.info` notifications appear in the Cursor chat as delegation progresses through compile → builder → executor steps. At least 5 milestone messages visible per delegation. *(Shipped in code; Cursor chat rendering is host-version dependent — `logs tail` is the reliable fallback.)*
3. **Live tail in side terminal** — `mcp-coder logs tail --latest` follows a live delegation in a second terminal, printing one human-readable line per trace event in real time.
4. **Stall → structured response** — when Aider asks to add files to chat, the delegation does not fail silently; it returns `{"status": "needs_input", "files_requested": [...]}` to Cursor so the planner knows exactly what to do.
5. **`policy_applied.ignored`** — executor events no longer misleadingly imply `temperature` / `top_p` were applied; `ignored` key present.
6. **Proxy toggle** — `MCP_CODER_PROXY_ENABLED=0` runs a delegation without the proxy for debugging; `backend_llm_call` events still captured.

## Strategic context

Phase 9 closed the observability infrastructure — 100% of LLM calls captured at the HTTP boundary, write-always, replayable, model registry + `policy_applied` on every event. The stack is now trustworthy from a logging perspective.

**The gap for real-project dogfood is behavioral:**
- Aider runs headless with `yes=True` — every prompt is auto-approved, scope creep is invisible until too late (**trust gap**).
- Long delegations are opaque — only a spinner in Cursor, nothing in the terminal until the tool returns (**visibility gap**).
- When Aider asks for more files, the delegation silently fails instead of routing the question back to Cursor (**stall gap**).
- `CallParams` already resolves `system_prompt_prefix` and `edit_format` from env — they are never applied to Aider (**executor capability gap**).

Phase 10 closes these four gaps at POC/partial level. The order is deliberate:
```
P10-001: Shape behavior BEFORE run   (executor options → reduce stalls)
P10-002: See what happens DURING run (visibility → MCP notifications + log tail)
P10-003: React when stalls OCCUR     (supervision → needs_input instead of failure)
P10-004: Backlog clearance           (high-ROI deferred items from Phase 9)
```

**Phase 10 is NOT:**
- Full inner-loop supervision (BL-350 outer loop continuation) — Phase 11
- AI-suggested model parameters (BL-513) — Phase 11
- Dynamic mid-delegation policy mutation (BL-514) — Phase 11
- Out-of-process backend proxy extension (Claude Code, Codex base URL) — Phase 11
- Multi-model escalation (BL-321) — Phase 11
- Critic/reviewer post-executor pass (BL-358, BL-006) — Phase 11

## Locked design decisions

*(Resolved in planning session 2026-06-18 — see [notes/phase10-master-session-bootstrap.md](./notes/phase10-master-session-bootstrap.md) for full reasoning.)*

| ID | Decision |
|----|----------|
| D-P10-1 | **Supervision v0 = output parsing + `needs_input` return.** No Aider `InputOutput` subclass in v0; no mid-loop injection. Pattern: executor finishes or is aborted → detect stall patterns in captured output → return structured `needs_input` payload. Auto-retry with files added as read-only is optional (configurable via `MCP_CODER_STALL_AUTO_RETRY=1`). |
| D-P10-2 | **Progress notifications via `ctx.info()`, not `ctx.report_progress()`.** `report_progress` requires a `progressToken` set by the client at call time — Cursor support is version-dependent. `ctx.info()` emits MCP `notifications/message` which Cursor renders as live status lines. More reliable for POC. |
| D-P10-3 | **Thread bridge via asyncio queue for P10-002.** Aider executor runs in a worker thread; `ctx.info()` is an async coroutine that must run on the event loop. Bridge: worker enqueues strings to a thread-safe queue; an asyncio task drains them with `await ctx.info(...)`. |
| D-P10-4 | **BL-334 v0 = env/yaml config only.** `system_prompt_prefix` is set globally per deployment, not per-delegation in the MCP call args (that is BL-512 Stage 2, Phase 11). This is intentional: observe behavior across many real-project delegations before adding per-call control. |
| D-P10-5 | **`system_prompt_prefix` applied via `model.system_prompt_prefix` on the Aider `Model` object before `Coder.create()`.** `edit_format` applied via `Coder.create(edit_format=...)`. Both are already resolved by `CallParams` / `model_registry.resolve()`; this is a wiring fix only. Backend-neutral: resolver in `core/config/`, application in `core/engine/aider_runtime.py`. |
| D-P10-6 | **`policy_applied.ignored` list for executor-inapplicable fields.** `temperature`, `top_p`, `max_tokens` resolved by registry but not applicable to Aider (Aider owns these). Add `"ignored": ["temperature", "top_p", "max_tokens"]` + optional `"note"` to executor surface `policy_applied`. Alternative (filter silently) rejected — losing the "set but no effect" signal is worse than showing the `ignored` key. |
| D-P10-7 | **Proxy toggle (`MCP_CODER_PROXY_ENABLED=0`) skips proxy start and leaves `*_API_BASE` env vars untouched.** Default on. When disabled: `proxy_llm_call` events absent; `backend_llm_call` + litellm callback still runs (partial capture). No new code paths; a single guard in `ensure_observability_bootstrap()`. |

### P10-002 — Visibility v0: MCP notifications + `logs tail` *(BL-106 POF + BL-520 POF)*

**Status:** `done` — worker delivered implementation + tests; accepted in master session 2026-06-18.

**Goal:** Emit live `ctx.info` notifications during delegation so Cursor shows progress, and add a `mcp-coder logs tail` CLI command that follows a running delegation in real time.

**Scope — Part A: MCP notifications**
- `server/mcp_server.py` — add `ctx: Context` parameter to `delegate_to_agent`; thread bridge: `asyncio.Queue` + drainer task or `asyncio.run_coroutine_threadsafe`
- `core/pipeline/` (or `mcp_server.py` pipeline call sites) — emit notifications at each stage boundary:
  - `[compile] Starting context compilation…`
  - `[compile] Context ready — builder output: N chars, context_refs: N`
  - `[architect] Running architect pass…` (if applicable)
  - `[validation] Spec validation passed / skipped`
  - `[executor] Starting Aider — step 1 of N`
  - `[executor] Step N complete (M LLM calls, K tokens)`
  - `[done] Delegation complete — success / needs_input / failure`
- Use `ctx.info(msg)` — no `report_progress` (see D-P10-2)
- Thread bridge: `ProgressQueue` helper class — worker calls `progress_queue.put(msg)`; async drainer calls `await ctx.info(msg)` on event loop
- Throttle: max 1 message per 2 seconds from executor to avoid noise

**Scope — Part B: `logs tail` CLI**
- `core/cli/logs_tail.py` — new file
- `mcp-coder logs tail [--workspace W] [--latest | --delegation-id <id>]`
  - `--latest`: find most recent `traces/*.jsonl` by mtime in workspace session dirs
  - `--delegation-id <id>`: follow specific trace file
  - Poll file for new lines (inotify / fsevents not required; poll interval ~0.5s acceptable)
  - Format each event type as a one-liner: `[<timestamp>] <event_type> <key_fields…>`
  - Event types to render: `trace_header`, `compile_event`, `executor_step`, `llm_call`, `proxy_llm_call`, `backend_llm_call`, `delegation_complete`
- Wire in `main.py` as `mcp-coder logs tail`
- Tests: unit tests for event formatter; integration test with a pre-written trace file

**Acceptance:**
- `ctx.info` messages appear as streamed lines in Cursor chat during a live delegation (manual dogfood verification)
- At least 5 messages emitted during a standard delegation (compile, builder, validation, executor start, done)
- `mcp-coder logs tail --latest` in a second terminal shows new events as they appear during a live delegation
- Event format is human-readable (not raw JSON) by default; `--format json` available
- No crash when trace file doesn't exist yet (graceful polling)
- Full suite green

**Implementation notes (worker report):**
- `server/mcp_server.py` now accepts `ctx: Context | None = None` in `delegate_to_agent`.
- Added `_DelegationProgressBridge` queue bridge to safely emit async `ctx.info(...)` from sync/threaded execution flow.
- Milestone notifications added at compile start/ready, validation status, executor start, and final outcome (`success` / `needs_input` / `failure`), with throttled executor-step updates.
- Notification failures are intentionally non-fatal.
- New CLI module `core/cli/logs_tail.py` adds `mcp-coder logs tail` with `--latest` / `--delegation-id` and `--format human|json`.
- `main.py` wired `logs tail` dispatch to `core.cli.logs_tail.main_logs_tail`.
- New test file: `tests/test_visibility_p10_002.py`.

**Validation evidence (worker + master rerun):**

### P10-003 — Stall detection → `needs_input` v0 *(BL-351 v0)*

**Status:** `done` — worker delivered implementation + tests; accepted in master session 2026-06-18.

**Goal:** When Aider asks to add files to the chat (the most common stall pattern), stop returning a generic failure. Instead return a structured `needs_input` response to Cursor with the list of requested files so the planner can act on it.

**Scope:**
- `core/engine/aider_engine.py` — enhance `infer_run_success` (or a new `infer_stall_type` function) to classify executor output into:
  - `success` — Aider completed the task
  - `needs_input_files` — detected "add files to chat" / "please add X to the chat" patterns; extract file paths
  - `needs_input_clarification` — detected open question / "I need to know…" patterns (regex match; no LLM needed)
  - `failure` — hard error unrelated to stall
- `server/mcp_server.py` (or `core/engine/execution_result.py`) — return structured response for `needs_input` stalls:
  ```json
  {
    "status": "needs_input",
    "reason": "executor_requested_files",
    "files_requested": ["src/foo.py", "tests/test_bar.py"],
    "message": "Aider needs access to additional files. Add them to target_files and retry.",
    "executor_output_tail": "…last 500 chars…"
  }
  ```
- Optional (configurable): `MCP_CODER_STALL_AUTO_RETRY=1` — when stall type is `needs_input_files`, add the requested paths as read-only to Aider context and retry once before escalating
- `core/engine/stall_patterns.py` — new file: compiled regex patterns for common stall messages (Aider "add files" variants)
- Record stall type in delegation JSONL (`stall_type`, `files_requested` fields)
- Tests: unit tests for each stall pattern; integration test for `needs_input` return shape

**Acceptance:**
- Delegation with Aider asking "Please add `src/config.py` to the chat" returns `{"status": "needs_input", "files_requested": ["src/config.py"]}` to Cursor — not a generic failure
- `stall_type: "needs_input_files"` recorded in delegation JSONL
- Cursor planner receives enough information to add the files and retry
- When `MCP_CODER_STALL_AUTO_RETRY=1`: file is added as read-only and Aider retries once; `auto_retried: true` in delegation record
- Hard failures (Aider crash, timeout) still return `status: failure` as before
- Full suite green

**Implementation notes (worker report):**
- `core/config/aider_runtime.py` now provides regex-only stall classification (`classify_executor_outcome`) plus helpers for file-path extraction, payload building, and auto-retry env gate.
- `core/engine/aider_engine.py` now emits stall audit metadata (`stall_type`, `files_requested`, `executor_output_tail`) on stall outcomes.
- `server/mcp_server.py` now maps stall metadata to structured `needs_input` responses and supports one-shot retry when `MCP_CODER_STALL_AUTO_RETRY=1`.
- `core/logging/delegation_log.py` now records `stall_type`, `stall_files_requested`, and `auto_retried` in delegation context.
- New tests: `tests/test_stall_needs_input_p10_003.py`; related delegate/spec-review tests updated.
