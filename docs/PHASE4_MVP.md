## Phase 4 thesis

> **mcp-coder actively builds and manages context** — not just records what happened. Phase 2 shipped the compiler (tiers, budget); Phase 3 gave it memory (workspace history, delegation RAG). Phase 4 closes the loop: a cheap-LLM pipeline inside mcp-coder assembles the right context before delegating, verifies outcomes after, and surfaces structured guidance back to Cursor. RAG is an *input* to this pipeline — Phase 5 decides what corpus it needs based on Phase 4 evidence.

**Key shifts from Phase 3:**

| Phase 3 had | Phase 4 adds |
|-------------|--------------|
| Compiler assembles context from planner hints | Builder LLM picks files + assembles brief automatically |
| Planner reads `delegation_diff` manually | MCP verify loop (optional pytest hook, partial outcomes) |
| Specs under `.mcp-coder/specs/tasks/` by convention | Hard enforcement + clearer error UX |
| Inspect tools present but underused | Judgment loop in response + rules enforcement |

## Architecture (summary)

Phase 4 extends the Phase 2 context compiler with an **active assembly layer** and a **verify loop**. The existing `assemble_context()` → `ContextPackage` → adapter chain is preserved; Phase 4 adds an optional cheap-LLM step before assembly and a post-delegation verify step.

```text
Pre-delegate:   [cheap LLM file picker] → assemble_context() → ContextPackage → Aider
Post-delegate:  delegation_diff → [optional verify: pytest / outcome check] → response to Cursor
Parallel:       planner UX fixes (spec path, inspect tools, error messages)
```

**Storage:** No new databases. Uses `workspace_history.db` (Phase 3) and `delegation_rag.db` (P3-002-lite) as inputs.

## Phase 4 architecture decisions (D-P4 — locked 2026-06-09)

| ID | Decision | Primary tasks |
|----|----------|---------------|
| D-P4-1 | Context builder is a cheap-LLM pass inside `delegate_to_agent` — Cursor stays thin | P4-001 |
| D-P4-2 | Verify loop is opt-in via config (`auto_verify: true`); not blocking by default | P4-010 |
| D-P4-3 | Spec paths **hard-reject** if not under `.mcp-coder/specs/tasks/`; error includes exact correct path + "move and retry" hint | P4-005 |
| D-P4-4 | Judgment loop: `delegation_diff` summary surfaced prominently in response; rules require cite before done | P4-005/P4-006 |
| D-P4-5 | Builder opt-out rule: P4-001a (rules-based file picker) ships **opt-out** from day one; P4-001b (cheap-LLM assembly) ships **opt-in**, flips to opt-out after Phase 4 dogfood confirms stability. Config key: `context_builder: false` to disable. Matches `rag_enabled` pattern. | P4-001 |
| D-P4-6 | P4-001a is rules-based (spec edit paths + ripgrep) — no LLM. When P4-001b needs a model: `CONTEXT_BUILDER_MODEL` env or `context_builder_model:` in config.yaml; **Gemini Flash default** (largest context window, cheapest). Same pattern as `AIDER_MODEL`. | P4-001b |
| D-P4-7 | Verify loop scope: configurable `test_command` (e.g. `pytest -x`); default = full suite when `auto_verify: true`. Spec-targeted test discovery deferred (fragile heuristic; false negatives worse than full suite). | P4-010 |
