# Phase 9 — Write-always storage + universal proxy + replay

**Status:** Active — master session complete 2026-06-14; milestones P9-001..P9-005 scoped; workers not yet tasked.
**Purpose:** Prove "100% LLM call captured" by adding a universal internal HTTP proxy (litellm → proxy → provider) that captures raw bytes before any normalization layer; flip the write gate to always-on; add context package blobs and replay CLI.
**PM board:** this file · **Issues:** [PHASE9_ISSUES.md](./PHASE9_ISSUES.md) (to be created)
**Phase 8 (frozen):** [PHASE8_MVP.md](./PHASE8_MVP.md) · [PHASE8_ISSUES.md](./PHASE8_ISSUES.md)
**Design notes:** [notes/phase9-master-session-bootstrap.md](./notes/phase9-master-session-bootstrap.md) · [notes/llm-interception-strategies.md](./notes/llm-interception-strategies.md)

## One-line goal

Capture every LLM byte at the HTTP boundary before litellm normalization, write it unconditionally, and make any delegation replayable from disk.

## North-star acceptance (dogfood)

After a live `delegate_to_agent` call at **any** verbosity setting:

1. **Full prompt + response bodies** in `traces/<id>.jsonl` — unconditionally, not gated on verbosity.
2. **Context package blob** at `sessions/<id>/context_packages/<hash>.json`.
3. **`proxy_llm_call` events** in trace — proxy fired for every LLM call made by any in-process caller; cross-check vs `backend_llm_call` shows no gaps.
4. **BL-507 resolved** — raw proxy log answers definitively whether thinking tokens are present at the HTTP boundary (ruling in or out litellm as stripping layer).
5. **`mcp-coder replay <delegation_id>`** reconstructs full delegation from disk — context package + prompt + every turn — no Cursor required.
6. **`mcp-coder maintenance gc --dry-run`** reports what would be pruned under the retention policy.

---

## Strategic context

Phase 8 shipped `ObservableModel` — Aider's inner-loop calls now appear as `backend_llm_call` events. This is excellent coverage but it operates above litellm's normalization layer. Whatever litellm silently drops (thinking blocks, provider extensions) is lost before we see it.

**Phase 9 closes the final gap:** a local HTTP proxy sits between litellm and the real provider. It captures the raw HTTP response before litellm normalizes it. If thinking tokens are present in the upstream's raw response, they will appear in the proxy log — provably. If they're absent from the raw response too, the upstream provider (e.g. OpenRouter) is the cause — which is an actionable, attributable finding.

The proxy also provides the universal architecture for Phase 10+ multi-backend capture: once `LocalLlmProxy` exists, pointing Claude Code / Codex / OpenCode at it is just a base URL config change.

**Phase 9 is NOT:**
- Out-of-process backend interception (Claude Code / Codex / OpenCode base URL config) — Phase 10+
- Inner loop control / BL-351 supervisor — Phase 10+
- Full re-execution replay (sandboxed) — Phase 10+
- Novelty / curation pipeline — after raw corpus exists

## Locked design decisions

*(Resolved in master session 2026-06-14 — see [notes/phase9-master-session-bootstrap.md](./notes/phase9-master-session-bootstrap.md) for full reasoning.)*

| ID | Decision |
|----|----------|
| D-P9-1 | **Proxy position: between litellm and real provider.** `api_base` overridden to `http://localhost:PORT` at bootstrap. litellm stays in the stack for request formatting and response normalization. Proxy is a transparent HTTP pass-through that logs and routes. |
| D-P9-2 | **Raw capture before litellm normalization.** Raw request + response bodies stored as-is. Field loss is provably attributed: present in raw → litellm dropped it; absent from raw → upstream provider dropped it. Makes "100% from our boundary" a provable statement. |
| D-P9-3 | **Per-session lifecycle.** Proxy starts once at MCP server bootstrap alongside `ensure_observability_bootstrap()`. All delegations share it. Context store handles per-call attribution. |
| D-P9-4 | **Model-prefix routing table from env vars.** `openrouter/*` → OpenRouter + key; `anthropic/*` → Anthropic + key; `openai/*` → OpenAI + key. No separate config. Callers send no API keys. |
| D-P9-5 | **Attribution via active context store.** In-process callers: proxy reads `delegation_id_var` + `step_index_var`. No header injection needed. Exact attribution. Out-of-process backends (Phase 10+): header injection or timing correlation. |
| D-P9-6 | **Dual capture during Phase 9.** `ObservableModel` (`backend_llm_call`) + proxy (`proxy_llm_call`) run simultaneously. Proxy is ground truth. Any call in proxy-only → gap in Phase 8 coverage identified. Phase 9 exit: gaps evidenced or absence of gaps proven. |
| D-P9-7 | **Phase 9 proxy scope: in-process callers only.** LlmGateway helpers + AiderEngine via litellm. Phase 10+ extends to out-of-process backends by pointing their base URL at the same proxy — no new proxy code needed. |
| D-P9-8 | **Write-always is the new default.** Verbosity levels (`lean`/`standard`/`full`) control display, CLI output, and RAG promotion only. They never gate what is written to disk. |
| D-P9-9 | **Proxy is an observability observer, not a separate writer.** `LocalLlmProxy` calls `get_observability().record_proxy_llm_call()` — the same pattern as `ObservableModel` calling `record_backend_llm_call()` (Phase 8). `ObservabilityBackend` gains one new abstract method; `LocalObservability` and `NullObservability` implement it. No separate write path, no file locking, no second schema. Write-always (D-P9-8) and verbosity filtering apply to proxy events automatically. |

## Milestones

### P9-001 — Write-always storage *(BL-367 core)*

**Status:** `pending`

**Goal:** Remove verbosity from the write gate. Trace files are written unconditionally for every delegation at all verbosity tiers. `lean`/`standard`/`full` become read/display/export filters only.

**Scope:**
- `core/observability/trace.py` — remove verbosity checks at write time; always write full bodies
- `core/config/` — `verbosity` config field semantics update (display-only annotation)
- `core/observability/local.py` — `record_*` methods write unconditionally
- Update any viewer / CLI output paths that format output based on verbosity (those remain; they just don't control what's on disk)

**Acceptance:**
- At `verbosity: lean`, full prompt + response bodies still present in `traces/<id>.jsonl`
- Verbosity flag only affects what `mcp-coder delegations show` prints
- Full suite green

---

### P9-002 — Context package blob sidecar *(BL-367 C1)*

**Status:** `pending`

**Goal:** Store the assembled context package for each delegation as a hash-deduplicated JSON blob on disk. Combined with the trace file and JSONL row, any delegation is fully replayable without Cursor.

**Scope:**
- At context-compile time: compute `sha256(json.dumps(package, sort_keys=True))`
- Write to `sessions/<session_id>/context_packages/<hash>.json` if not already present (dedup by hash)
- Record `context_package_hash` in the `delegations.jsonl` row and in `trace_header` event
- Graceful degradation if package is unavailable (None hash, no blob)

**Acceptance:**
- After a delegation: `sessions/<id>/context_packages/<hash>.json` exists
- Re-delegating with same context: same hash, no duplicate blob written
- `delegations.jsonl` row includes `context_package_hash`

---

### P9-003 — Universal internal proxy *(BL-508)*

**Status:** `pending`

**Goal:** Spin up `LocalLlmProxy` at MCP server bootstrap. All in-process LLM callers (LlmGateway helpers + AiderEngine via litellm) route through it. Proxy captures raw HTTP request + response before litellm normalization. Emits `proxy_llm_call` events into the trace. Cross-checks against `backend_llm_call` events from Phase 8.

**Scope:**
- `core/proxy/local_proxy.py` — async HTTP server (aiohttp or httpx-based); OpenAI Chat Completions format; model-prefix routing table from env vars; streaming SSE tee; calls `get_observability().record_proxy_llm_call()` on completion
- `core/proxy/routing.py` — routing table builder from env; `(model_prefix → upstream_url, api_key)` map
- `core/observability/base.py` — new abstract `record_proxy_llm_call()` method (same pattern as `record_backend_llm_call()` added in P8-001)
- `core/observability/local.py` + `null.py` — implement `record_proxy_llm_call()`
- `core/observability/trace.py` — new `build_proxy_llm_call_record()` event builder
- `core/observability/bootstrap.py` — `ensure_observability_bootstrap()` starts proxy; overrides `LITELLM_API_BASE` in process env
- `core/observability/context.py` — proxy reads `delegation_id_var` + `step_index_var` per-request for attribution
- Cross-check: after each delegation, `LocalObservability` can report any `proxy_llm_call` with no matching `backend_llm_call` (coverage gap detection)

**Acceptance:**
- After a delegation: `traces/<id>.jsonl` contains `proxy_llm_call` events for every LLM call
- Raw response body present on `proxy_llm_call` event — not truncated
- `proxy_llm_call` and `backend_llm_call` agree on call count (no gaps)
- BL-507: if thinking blocks appear in raw response, they are present in `proxy_llm_call.raw_response`
- Streaming delegations work — proxy tees SSE without blocking Aider

### P9-004 — Replay CLI (dry) *(BL-367 E1–E5)*

**Status:** `pending`

**Goal:** `mcp-coder replay <delegation_id>` reconstructs the full delegation from disk: context package, prompt, every executor turn + backend call + proxy call, code diff. No re-execution. No Cursor required.

**Scope:**
- `core/cli/replay.py` — load `delegations.jsonl` row → load context package blob → load `traces/<id>.jsonl` → format and print
- Output: structured summary of every event in the delegation (context → prompt → turns → outcomes)
- Handle missing blobs gracefully (partial replay)
- `mcp-coder replay --format json` for machine-readable output

**Acceptance:**
- `mcp-coder replay <id>` prints full delegation reconstruction with no network calls
- Context package shown (or "not available" if blob missing)
- All `backend_llm_call` + `proxy_llm_call` events shown with model, usage, timing
- Exit code 0 if successful, 1 if delegation_id not found

### P9-005 — Storage GC first slice *(BL-357 first pass)*

**Status:** `pending`

**Goal:** Add retention policy enforcement — TTL config, dry-run reporting, promote-then-prune safety. First pass only: no archival, no global promotion store.

**Scope:**
- `core/cli/maintenance.py` — `gc` subcommand with `--dry-run` flag
- Config: `retention_days` per tier (traces, blobs, JSONL rows) with defaults
- Dry-run output: disk usage by layer, what would be pruned, what is blocked (no promoted artifact yet)
- Actual prune: delete trace files + blobs where all rows older than TTL; never delete JSONL delegation rows without explicit flag
- `maintenance stats` updated to show disk usage breakdown

**Acceptance:**
- `mcp-coder maintenance gc --dry-run` reports by layer without deleting anything
- `mcp-coder maintenance gc` prunes expired traces respecting promote-then-prune
- `maintenance stats` shows bytes per layer
