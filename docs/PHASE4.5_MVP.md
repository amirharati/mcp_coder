## Why this exists

The project was built fast — AI-assisted, spec-driven, with a deliberate "ship then understand" pace. That worked for velocity. But entering Phase 5 without understanding the real system would mean designing RAG for an imagined tool.

**What we actually need:**

> *"I can't even claim to fully understand the details and current architecture in enough detail, since we clearly do things a bit differently than we describe in specs or high-level files."*

Phase 4.5 is the answer: systematic onboarding onto the real stack — not the spec, the running code — so every Phase 5+ decision is grounded in evidence.

**This covers Phases 1–4**, not just Phase 4:

- How does session/storage/linking actually work (Phase 1)?
- What does the context compiler actually produce (Phase 2)?
- What is in workspace history and how does RAG work in practice (Phase 3)?
- What does the pipeline + builder LLM actually do to the prompt (Phase 4)?

## What we built (Phases 1–4 summary)

```
Phase 1  Delegate + pass-through context + sessions
         MCP → Aider; home storage (~/.mcp-coder); spec-as-contract; host transcript

Phase 2  Context compiler
         assemble_context() → ContextPackage; tiers (edit-full, read-excerpt, pointer, map-only);
         budget; inspect-context dry-run; model cost telemetry

Phase 3  Workspace truth + memory
         workspace_history.db; manifest walk (git-agnostic files_changed);
         versioned specs; attempt archive; post-gateway;
         delegation RAG code shipped (core/rag/ FTS5 + rag_search MCP) but
         **usage deferred — not integrated into pipeline; scope → Phase 5**

Phase 4  Active context builder + pipeline
         Rules file picker; cheap-LLM builder brief (Gemini Flash);
         per-role model registry; opt-in spec validation; opt-in architect pass;
         delegation_pipeline phase audit; opt-in auto_verify
```

## The full delegation pipeline (what happens on `delegate_to_agent`)

```
Cursor (planner) → mcp-coder → Aider (executor)

mcp-coder delegate_to_agent(mode=implement, spec_path=..., ...)
  │
  ├─ 1. spec_read          parse spec contract (Files edit/read, policies, outcome rules)
  ├─ 2. spec_validation*   cheap LLM: spec vs host transcript → clarification_needed?
  ├─ 3. file_picker        ripgrep + spec paths + repo map → candidate_files
  ├─ 4. context_assemble   compiler: tiers → ContextPackage → mechanical brief
  ├─ 5. architect_pass*    cheap LLM: ## Architect plan above brief
  ├─ 6. builder_llm        cheap LLM: ## Builder brief (narrative) merged on top
  ├─ 7. executor           Aider: SEARCH/REPLACE edits to disk
  ├─ 8. post_gateway       manifest diff → files_changed; judgment_checklist; suggested_edit_paths
  ├─ 9. spec_report        write .mcp-coder/specs/reports/*.md
  └─ 10. auto_verify*      pytest → outcome: success / partial

* = opt-in via config.yaml
```
