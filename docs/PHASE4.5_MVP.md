## Why this exists

Phase 4 shipped a layered delegation pipeline. But:

- Operator literacy is thin — what exactly is in the prompt Aider sees?
- Token telemetry is broken (BL-335 — all `model_roles.*.tokens` are `None`)
- Executor quality gap (BL-338 — gpt-4o-mini fails multi-file tasks repeatedly)
- Phase 5's RAG scope should be grounded in evidence, not theory

**Phase 4.5 produces that evidence.** Findings feed directly into Phase 5 planning.

---

## The pipeline we're inspecting

```
delegate_to_agent (one MCP call, mode=implement)
  │
  ├─ spec_read               — parse spec contract (Files edit/read, policies)
  ├─ spec_validation (opt)   — cheap LLM: spec vs chat → clarification_needed
  ├─ file_picker             — ripgrep + spec paths + repo map → candidate_files
  ├─ context_assemble        — compiler: tiers (edit-full, read-excerpt, pointer, map-only) → ContextPackage
  ├─ architect_pass (opt)    — cheap LLM: ## Architect plan above brief
  ├─ builder_llm (default)   — cheap LLM: ## Builder brief (narrative) merged above mechanical ## Paths
  ├─ executor                — Aider: edits, SEARCH/REPLACE
  ├─ post_gateway            — workspace diff, judgment_checklist, suggested_edit_paths
  ├─ spec_report             — write .mcp-coder/specs/reports/*.md
  └─ auto_verify (opt)       — pytest → outcome: success / partial
```

**Config flags** (`.mcp-coder/config.yaml`):

| Flag | Default | Controls |
|------|---------|----------|
| `context_builder` | on | file picker + repo map |
| `context_builder_llm` | on | builder LLM brief |
| `architect_pass` | off | architect LLM pass |
| `spec_validation` | off | pre-delegate spec check |
| `auto_verify` | off | post-delegate pytest |
| `host_transcript` | `none` | transcript dump policy |

### Track 4 — Gap analysis

**Goal:** Produce a written gap report to feed Phase 5 planning.

| Area | Known gap | Phase 5 implication |
|------|-----------|---------------------|
| **Token telemetry** | All `model_roles.*.tokens = null` (BL-335) | Cannot measure builder vs executor cost → RAG cost budgeting blind |
| **Executor quality** | gpt-4o-mini fails SEARCH/REPLACE on multi-file (BL-338) | Need model guidance or auto-escalation before more features |
| **Builder brief quality** | No ground truth — is the brief actually improving Aider output? | Need eval metric before spending on RAG inputs |
| **Picker recall** | Does the picker miss relevant files in brownfield? When? | Determines whether workspace-file RAG is needed |
| **Delegation RAG usage** | Is `rag_search` being used by planners in practice? | If not, Phase 5 workspace RAG will have same adoption problem |
| **inspect-context parity** | Dry-run includes builder LLM; architect pass and validation not yet (check) | Inspection blind spots |
