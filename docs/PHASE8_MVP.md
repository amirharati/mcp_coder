## One-line goal

Capture every Aider LLM call — inner turns, thinking tokens, exact attribution — so no LLM event is invisible after a delegation.

## North-star acceptance (dogfood)

After a live `delegate_to_agent` call on `mcp_coder_phase1_e2e`:

1. **Every Aider inner-loop LLM call** (not just the outer executor step events from P7-002) appears as a `backend_llm_call` event in `traces/<delegation_id>.jsonl` with `call_type: executor_turn`.
2. **Thinking tokens** (`thinking_text`, `thinking_tokens`) are present on `backend_llm_call` events when the model emits them (e.g. Claude with extended thinking, o-series reasoning).
3. **Exact attribution** — `delegation_id` and `step_index` present on every `backend_llm_call` event, matching the outer executor step events from P7-002.
4. **Cache-warming pings** (`warm_cache_worker`, `max_tokens=1`) tagged as `call_type: cache_warm` in the trace — no silent calls.
5. **Backend contract** documented for Aider adapter — lists verified interception paths, known gaps, and the approach used.

---

## Strategic context

Phase 7 shipped three layers of visibility:
- Helper LLM calls through `LlmGateway` (P7-001)
- Executor outer-loop step events: `llm_call`, `tool_call`, `action` (P7-002)
- Compile provenance bundle (P7-003)

**What is still missing after Phase 7:**

| Gap | Why it matters |
|-----|----------------|
| Aider inner-loop sub-calls | Aider makes 2–10 LLM calls per delegation internally (multi-turn edit, lint retry, tool confirm). P7-002 outer loop sees one "step" per sub-run; the individual LLM round-trips within that step are invisible. |
| Thinking tokens | Extended thinking (Claude, o-series) produces the highest-value training signal. Aider receives it but does not forward it; it is permanently lost today. |
| `warm_cache_worker` pings | Background `max_tokens=1` probe calls `litellm.completion()` outside the `send_completion()` seam — silently fires during delegations. |

Phase 8 fixes all three. It is **passive observation only** — no control, no injection, no intervention.

**Phase 8 is NOT:**
- Write-always storage (Phase 9) — we capture first, then flip the write gate once capture is complete
- Inner loop control / BL-351 supervisor (Phase 10+) — visibility before intervention
- HTTP proxy for Claude Code / Codex / OpenCode (Phase 10+) — Aider is the primary backend today

## Locked design decisions

*(Resolved in master session 2026-06-13 — see [notes/llm-interception-strategies.md](./notes/llm-interception-strategies.md) for full reasoning.)*

| ID | Decision |
|----|----------|
| D-P8-1 | **Aider interception via `ObservableModel` subclass of `aider.models.Model`.** Override `send_completion()` — the single verified seam for all real Aider LLM calls across all providers. No monkey-patching, no sys.modules injection, no litellm package substitution. `ObservableModel` is passed to `Coder.create(main_model=...)` by `AiderEngine`. Rationale: ~20 lines of Python, zero new infrastructure, typed OOP, `TypeError` on signature drift. See notes/llm-interception-strategies.md § 2a. |
| D-P8-2 | **`warm_cache_worker` covered by Route A callback extension.** `warm_cache_worker` in `aider/coders/base_coder.py:1373` calls `litellm.completion()` directly, bypassing `send_completion()`. Route A (`success_callback`) already fires for it. Extend the callback to detect `max_tokens == 1` probes and emit a `backend_llm_call` event with `call_type: cache_warm`. No new infrastructure. This is a low-value call (no LLM content) but closes the coverage gap. |
| D-P8-3 | **New event type `backend_llm_call` in the existing trace schema.** Fields: `delegation_id`, `step_index`, `call_type` (`executor_turn` \| `cache_warm`), `model`, `thinking_text`, `thinking_tokens`, `usage`, `timestamp`. Written to the same `traces/<delegation_id>.jsonl` file as all other events. Verbosity controls body storage consistent with existing `llm_call` events. |
| D-P8-4 | **Thinking token schema: normalized fields, not provider-native.** `thinking_text: str | null` and `thinking_tokens: int` on every `backend_llm_call` event. litellm normalizes provider differences (Anthropic `thinking` content block vs OpenAI `reasoning_content`). Our trace schema uses the normalized form for cross-provider replay fidelity. |
| D-P8-5 | **Backend interception contract: `InterceptionProfile` dataclass per adapter.** Each backend adapter carries an `InterceptionProfile` with: `strategy` (enum: `subclass` \| `proxy` \| `callback`), `verified_call_sites` (list of file:line strings), `known_gaps` (list), `thinking_captured` (bool). `AiderEngine` profile: strategy=`subclass`, verified=`[models.py:970]`, gaps=`[base_coder.py:1373 via callback fallback]`, thinking=`True`. |
| D-P8-6 | **Streaming capture via transparent iterator wrapper** — do not require `--no-stream`. `ObservableModel` wraps the stream returned by `super().send_completion()`, accumulates chunks, emits `backend_llm_call` on exhaustion. See P8-ISS-003. |

## Milestones

### P8-001 — `ObservableModel`: Aider inner-loop capture *(BL-371 core)*

**Status:** `done` — worker implementation delivered in [docs/tasks/P8-001-observable-model-v1.md](../tasks/P8-001-observable-model-v1.md) § Results; live dogfood after P8-001a confirms `backend_llm_call` capture and attribution (`70d63f1a-c7fc-4633-ac6d-dd3f2285e3f7`, `334072d7-2a19-46a2-853b-7a12dc481f3f`). A5 investigation completed: complex Sonnet run (`86fe232f-3bdd-4d04-a9e3-bdcbd3d8ce63`) emitted no reasoning fields, treated as provider/path-dependent behavior (see P8-ISS-004).

**Goal:** Subclass `aider.models.Model` to override `send_completion()`. Every Aider LLM call — across all providers, all turn types — emits a `backend_llm_call` event with thinking tokens and exact attribution. Wire `AiderEngine` to instantiate `ObservableModel` instead of `aider.models.Model`.

**Depends on:** Phase 7 (LlmGateway + observability seam must exist)

**Scope:**
- `core/engine/observable_model.py` — `ObservableModel(aider.models.Model)` subclass
- Override `send_completion()`: call `super()`, extract thinking blocks from result, emit `backend_llm_call` event via `get_observability()`
- **Dedup guard (P8-ISS-002):** prevent Route A `success_callback` from double-recording calls already captured by `ObservableModel` — add `_backend_call_active` flag in `litellm_callback.py` (same pattern as P7-001's `_gateway_call_active` guard)
- Extend `core/observability/litellm_callback.py`: detect `max_tokens == 1` probes, emit `cache_warm` event (D-P8-2)
- Update `core/observability/base.py` + `local.py` + `null.py`: new `record_backend_llm_call()` method
- Wire `core/engine/aider_engine.py`: pass `ObservableModel` to `Coder.create(main_model=...)`
- Thinking normalization helper: `extract_thinking(result) → (text, tokens)` using litellm response fields
- Flag `owned_completion.py` for deprecation (P8-ISS-001)
- Flag `aider_output_parse` token counting for deprecation — `ObservableModel` now provides exact per-call tokens (P8-ISS-005)

**Acceptance:**
- After a live delegate: `traces/<delegation_id>.jsonl` contains ≥1 `backend_llm_call` line with `call_type: executor_turn`
- `thinking_tokens > 0` on at least one event when using a thinking-capable model (e.g. `claude-3-7-sonnet` with extended thinking, or equivalent)
- `step_index` matches outer-loop `llm_call` step_index for the same step
- `cache_warm` event present when Aider cache-warming fires
- All existing tests green; new unit tests for `ObservableModel` with mocked `super()` and mocked observability

**Files touched:** `core/engine/observable_model.py` (new), `core/engine/aider_engine.py`, `core/observability/base.py`, `core/observability/local.py`, `core/observability/null.py`, `core/observability/litellm_callback.py`, `tests/`

### P8-002 — Backend interception contract *(BL-371 contract)*

**Status:** `done` — implementation delivered in [docs/tasks/P8-002-interception-contract-v1.md](../tasks/P8-002-interception-contract-v1.md) § Results; full pytest pass (798/1); joint dogfood validated `maintenance stats --verbose` interception output.

**Goal:** Define and attach an `InterceptionProfile` to every backend adapter. Aider's profile is populated from P8-001 data. The contract makes interception strategy explicit and auditable — any future backend added without a profile fails at startup.

**Depends on:** P8-001 (profile fields reference verified P8-001 call sites)

**Scope:**
- `core/engine/interception_profile.py` — `InterceptionProfile` dataclass (D-P8-5)

- `AiderEngine.interception_profile` returns populated profile from P8-001 audit
- Startup assertion: if any registered adapter has `thinking_captured=False` and thinking is expected, emit a warning
- `mcp-coder maintenance stats` reports interception profile per backend in debug output

**Acceptance:**
- `mcp-coder maintenance stats --verbose` shows Aider's interception profile
- Adding a mock adapter without `interception_profile` raises `TypeError` at instantiation (abstract property enforcement)
- Profile fields match the verified audit data from P8-001

**Files touched:** `core/engine/interception_profile.py` (new), `core/engine/base_engine.py` (or equivalent adapter base), `core/engine/aider_engine.py`, `core/cli/maintenance.py`, `tests/`
