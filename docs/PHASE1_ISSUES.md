## Issue details

### P1-ISS-001: Active Cursor chat ≠ newest mtime

**Status:** `done` (partial) — closed 2026-06-04 at P1-130. Multi-chat same-repo edge cases remain; see P1-140 / BL-109.

**Found:** P1-120 review (2026-06-04).

**Problem:** `CursorHostProvider` picks the **most recently modified** `agent-transcripts/**/*.jsonl` under the project slug. That may not be the Composer chat the user is in when they call `delegate_to_agent` (several chats → wrong `host_session_id` on metadata).

**Impact:** Metadata/linking. Wrong link still allows delegation; `align_host` may attach to wrong session folder if scoring picks wrong chat.

**Mitigation shipped (P1-130):** score = max(transcript mtime, last delegation per host id); 10s tie window; `host_resolve_method` in logs.

**Remaining directions (P1-140 / P1-199):**

- Prefer transcript whose mtime is within last N minutes only.
- Match transcript uuid to something Cursor exposes later (MCP / env).
- Optional MCP arg `host_session_id` from planner when known.
- Scan transcript tail for workspace path / recent user message (expensive).

**Acceptance (when closed):** **P1-130** — score = max(transcript mtime, last delegation per host id); tie window + `host_resolve_method` in logs. **Closed 2026-06-04** with caveat: multi-chat same repo still ambiguous; E2E used `score_global` successfully.

### P1-ISS-011: Global server log interleave

**Status:** `wontfix-p1` — accepted limitation at P1-125; revisit only if garbled lines show up in daily use.

**Found:** P1-125 worker § Results (multi-workspace / concurrency).

**Problem:** With default `server_log_scope: global`, every MCP stdio process appends to one file. Lines interleave but are tagged with `pid`, `workspace_path`, `project_key`. No file locking; under heavy parallel writes a rare **corrupted JSON line** is possible (POSIX `O_APPEND` is usually fine for small lines).

**Mitigation (no code):** Set `server_log_scope: project` (or `both`) in workspace `config.yaml` for repos you run in parallel.

**If we fix later:** file locking, per-pid subfiles, or default scope change — [BACKLOG.md](./BACKLOG.md) BL-308.

### P1-ISS-009: MCP process stale after code deploy

**Status:** `done` — mitigated 2026-06-06 at P1-152 (README/INSTALL ops). Optional code: [BL-306](./BACKLOG.md#observability--ops).

**Found:** P1-130 E2E review (2026-06-04).

**Problem:** Cursor spawns a long-lived `python main.py --mcp` child. Python imports modules once at startup. Editing mcp-coder on disk does **not** update the running process. User saw `fallback:always_new` in logs while on-disk code had P1-130 — toggling MCP in Settings was insufficient; process from 2:49 PM survived until Reload Window.

**Impact:** False-negative E2E; appears as “restart didn’t work.”

**Mitigations shipped:** `core/server/singleton.py` (kill stale per workspace on next start); Makefile `mcp-smoke` / `mcp-kill`; startup log includes `pid=`.

**Action:** Document ops workflow: **Reload Window** after code changes; do not run manual `make mcp` alongside Cursor MCP. Optional: startup `code_version` / git hash in stderr (BL-306).

### P1-ISS-012: Weak-model / upstream API errors break workflow

**Status:** `wontfix-p1` — accepted at Phase 1 exit; job may fail on cheap models, but **workflow must not poison workspace/UX** — fix in Phase 2+ ([BL-309](./BACKLOG.md#bl-309-delegation-hardening-job-failure-vs-workflow-failure)).

**Found:** Phase 1 E2E `mcp_coder_phase1_e2e` expense-splitter (2026-06-05).

**Problem:** When OpenRouter’s upstream route fails (observed: **Qwen 2.5 Coder via Cloudflare**, HTTP **500**, `finish_reason: 'error'`), LiteLLM raises a pydantic parse error. Aider surfaces a huge exception dump. Side effects leak past “delegation failed”:

| Symptom | Cause |
|---------|--------|
| **Empty stub files** left in repo | Aider creates target files before LLM fill; API dies mid-run |
| **Browser tabs** (`stripe.com`, `errors.pydantic.dev`, …) | `check_and_open_urls()` regex-scans exception text; headless `InputOutput(yes=True)` auto-confirms `webbrowser.open()` — Stripe URLs come from OpenRouter **`permissions-policy` HTTP headers** embedded in the error dump, not the user task |
| **Long hangs** (87–250s) | Aider/LiteLLM internal retries on 5xx |
| **Opaque tool output** | Full HTTP headers + tracebacks returned to Cursor |
| **`success: true` + `files_changed: []`** | Small single-file runs: model replied but edits not applied (separate from 500s) |

**Impact:** Operator loses trust (“is it still running?”, random browser storm). Repo left in partial/blocked state. **Not** a config bug — `mcp-coder test-model` (Aider path) passed on the same Qwen model with a tiny prompt; **Claude Sonnet 4** completed the same step-1 task in ~29s (`da11a5cd`).

**Principle:** Weak models may **fail the job** (bad code, no edits). They must not **break the workflow**.

**Mitigation today (ops):**

- `mcp-coder test-model` before large delegates
- Smaller single-file `delegate_to_agent` calls on cheap models
- Stronger model for multi-file steps (`AIDER_MODEL=openrouter/anthropic/claude-sonnet-4` worked in E2E)
- Read `~/.mcp-coder/server.jsonl` + session `delegations.jsonl`

**Replication:** See [BACKLOG.md BL-309](./BACKLOG.md#bl-309-delegation-hardening-job-failure-vs-workflow-failure) § How to replicate.

**Target (Phase 2+):** BL-309 — headless URL policy, classified errors, optional MCP-layer retry, empty-file guard, cleaner Cursor surface.

**Acceptance (when closed):** Upstream 500 on cheap model → `success: false`, short classified `error`, no browser opens, no 0-byte stubs (or rollback), spec § Blockers updated; delegation completes in bounded time.

### P1-ISS-013: `delegated_ok` ≠ planner test verify

**Status:** `wontfix-p1` — **by design** at Phase 1 exit; planner owns verification ([PHASE1_MVP.md](./PHASE1_MVP.md) D-SPEC-3).

**Found:** Expense-splitter E2E step 2 (2026-06-05, session `3fc37a15…`).

**Problem:** MCP report status `delegated_ok` and tool `success: true` mean the **delegation run completed** (Aider applied edits or review returned text). They do **not** mean acceptance criteria or `pytest` pass. Step 2 required **three** implement delegates before 13 tests green; each intermediate run was logged as success.

**Impact:** Planner must run tests and send fix-up delegates; trusting MCP alone marks steps done too early.

**Mitigation today:** Cursor rules: verify tests after implement; update task `Done when` only after local `pytest`.

**Target (Phase 2+):** [BL-310](./BACKLOG.md#bl-310-planner-verify--report-status-split) — optional `verified_ok` report status, pytest hook, or explicit `outcome: partial` when tests fail post-apply.
